## 九、处理建议

### 压缩与格式

1. 运行首选图继续使用 `optimized/generated-themes/**/*.webp`；目前最大单张仅 0.34MB，收益已经明确。
2. raw PNG 不建议靠简单 `sharp().png()` 直接压成 palette PNG：抽查 `hakurei-scene.png` 时，palette 版本可从 2.61MB 降到 0.89MB，但像素通道大量变化；无 palette 的无损重编码仅降到 2.58MB，收益很小。
3. 若仍需保留 PNG 回退，建议后续用 `oxipng` / `zopflipng` 做无损压缩并逐图校验像素；不要用有损量化替换源图，除非经过 UI 视觉复核。
4. `source-sheet-v1.png` 只用于重切参考，运行组件没有读取；公开包可排除或迁出 `public/`，保留在非公开素材档案目录。
5. 静态仪式预览图若只用于 UI 展示，应继续发布 WebP；PNG 仅保留为源文件或回退，不应作为公开包主资产。

### 尺寸

1. 场景背景 WebP 当前在运行层体积合理，优先保持横图构图和 UI 留白。
2. 动画拆层建议继续保持 1024x1024 透明 WebP；仅在移动端视觉收益明确时再生成小尺寸派生图。
3. 结果角标和 FX 层应优先控制在 512-1024px 范围，避免重复带入大 source sheet。

### 懒加载

1. 首屏只应预加载当前聚焦路线的 `sceneImage`，不要一次性预取 14 条路线背景。
2. 进入某条路线后再预载该路线 7 个 `ritualAssets`；结果角标可在结果卡渲染前后懒加载。
3. 音频不要 `preload="auto"` 拉满所有曲目；当前代码每次只创建一个随机 track，但被选中的 MP3 会完整加载，建议公开版本改为轻量自有 loop 或默认使用 Web Audio 合成。
4. 若未来取消 PNG 回退，请同步调整 `optimizedImageFallbackPath()` 的发布策略，避免页面仍尝试访问被裁掉的 raw PNG。

### 发布包裁剪

建议新增发布前裁剪步骤，但本轮不直接改 `.github/workflows/pages.yml`，因为 AI-4 本次允许修改范围不包含发布工作流：

1. 使用 `npm run build:public` 生成 GitHub Pages 包；该脚本会从 `out/images/generated-themes/legacy/` 删除所有文件。
2. `build:public` 会删除 raw PNG 场景 / 仪式源图和 `source-sheet-v1.png`，只保留运行所需 SVG 装饰、纹理和优化 WebP。
3. `build:public` 会保留 `out/images/characters` 与 `out/audio/music`；如果未来公开传播这些资源，仍建议先替换为项目自有或明确授权素材。
4. 后续 GitHub Pages 工作流应调用 `npm run build:public` 而不是普通 `npm run build`。

## 十、合规观察

- 官方二次创作指南要求明确标注这是东方 Project 二次创作，且不得让人误以为官方内容；英文指南也说明不能包含从官方游戏中抽出的素材，浏览器游戏和手机游戏只能免费发布。参考：`https://touhou-project.news/guideline/`、`https://touhou-project.news/guidelines_en/`。
- `public/images/generated-themes/` 的场景与仪式图经文件名、配置引用和 contact sheet 抽查，未见官方游戏截图、文字水印、Logo 或角色人物素材。
- `public/audio/music/*.mp3` 的公开授权证据不足。当前个人自用构建默认保留并加载这些 MP3；若未来公开传播，应替换为项目自有音频，或补齐授权和署名。

## 十一、本轮是否需要新增素材

不需要。缺失引用为 0，14 路线已有运行 WebP、PNG 回退、静态仪式图和动画拆层。后续如新增或替换素材，继续遵守：

- 明亮、干净、日式二次元游戏资产。
- 无人物、无文字、无水印、无 Logo。
- 非照片，不使用原作游戏素材。
- 不覆盖旧图，使用 `-v2`、`-v3` 或拆层名版本化落盘。
